# Motor_Test

基于 `Chassis_Motor_Driver` 的 STM32F103C6T6 双路电机快速筛查固件。

这个工程不使用 CAN。上电后，板子本地自动给两个电机插座输出相同的测试波形，同时读取两路编码器计数。适合快速筛查大量电机的“能否转动”和“编码器是否有脉冲”。

## 硬件映射

| 逻辑通道 | 电机 PWM | 编码器 A/B | 计数器 |
|---|---|---|---|
| 电机 1 / 插座 1 | TIM2_CH1/PA0、TIM2_CH2/PA1 | PA8、PA9 | TIM1 |
| 电机 2 / 插座 2 | TIM2_CH3/PA2、TIM2_CH4/PA3 | PA6、PA7 | TIM3 |

PWM 输出范围为 `-999` 到 `999`，本测试使用 `±999` 的满幅 PWM 指令。实际转速仍取决于供电、电机、负载和驱动功率级。

## 自动测试波形

每个周期 8 s，两路同时执行：

| 时间 | 阶段 | PWM 指令 |
|---:|---|---:|
| 0–0.5 s | 上电/换向停机窗口 | 0 |
| 0.5–1.3 s | 正向满幅阶跃 | `+999` |
| 1.3–1.6 s | 停机窗口 | 0 |
| 1.6–2.4 s | 反向满幅阶跃 | `-999` |
| 2.4–2.7 s | 停机窗口 | 0 |
| 2.7–4.7 s | 正向到反向斜坡 | `+999 → -999` |
| 4.7–6.7 s | 反向到正向斜坡 | `-999 → +999` |
| 6.7–8.0 s | 周期结束停机窗口 | 0 |

因此肉眼可以快速观察：正转、反转、换向、低速斜坡，以及两路是否都工作。

## 编码器验证

Ozone 中观察全局变量 `motor_test_debug`：

- `motor1_pwm_command`、`motor2_pwm_command`：固件实际下发的 PWM 指令；
- `motor1_delta_pulse`、`motor2_delta_pulse`：最近 10 ms 的编码器增量；
- `motor1_total_pulse`、`motor2_total_pulse`：累计编码器脉冲；
- `encoder_seen_mask`：bit0 表示电机 1 至少收到过非零脉冲，bit1 表示电机 2 至少收到过非零脉冲；
- `phase`：当前波形阶段，0 到 7；
- `cycle_count`、`cycle_time_ms`：测试循环进度。

判定建议：

1. 电机实际转动，且对应 `total_pulse` 持续变化：电机和编码器基本正常。
2. 电机转动但 `total_pulse` 不变：优先检查编码器插头、A/B 相线、编码器供电和对应插座映射。
3. `motor*_pwm_command` 在变化但电机不动：优先检查电源、驱动功率级、电机线和插座接触。
4. `total_pulse` 有变化但方向与另一只相反：可能只是电机/编码器相位或安装方向不同，不应仅凭正负号判定故障。

## 构建与下载

在本目录执行：

```powershell
mingw32-make -j2
```

输出文件：

```text
build/Motor_Test.elf
build/Motor_Test.hex
build/Motor_Test.bin
```

## 热插拔注意事项

固件在每个周期有停机窗口，但它没有电流检测、插座存在检测或硬件电子保险丝，无法判断电机是否已经插入。因此：

- 只有在板卡和插座本身明确支持带电热插拔时，才允许带电插拔；
- 更换电机前优先等到停机窗口，并确认机械端没有被夹住；
- 满幅 PWM 和快速反转可能产生较大的启动/制动电流，首次上电应架空电机、限流供电并准备断电；
- 不要把“PWM 指令已变化”当作“电机和编码器已通过”。最终仍需结合实际转动、编码器累计脉冲和供电电流判断。

## 与源工程的差异

本工程复用了源工程的 MCU、时钟、TIM1/TIM2/TIM3、PWM 引脚、编码器引脚和电机底层驱动，但删除了 CAN 外设、CAN 协议、速度 PID 和 CAN 状态上报。电机测试指令由 `App/motor_test.c` 本地生成，编码器只用于观察和筛查，不参与闭环调速。
